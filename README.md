# 鞋服店进销存记账软件

零部署、可离线、手机 + 电脑双端可用的鞋服店进货 / 销售 / 库存 / 记账工具。
无需服务器，数据全部保存在本机浏览器（IndexedDB）。

> **V3 多店铺版**：一套系统支持多店铺独立登录、独立数据、独立云同步，详见[「〇、V3 多店铺账号体系」](#v3-多店铺账号体系)。

---

## 〇、V3 多店铺账号体系

从 V3 起支持**多店铺多账号**：

### 1. 预置账号（初始密码均为 `000000`）

| 账号 | 店名 | 登录名 | 经营范围 | 数据 |
| --- | --- | --- | --- | --- |
| 账号 1 | 鞋店 | `shoe` | 鞋 | 承接 V2 存量数据 |
| 账号 2 | 服装店 | `clothes` | 服装 | 独立空库 |
| 账号 3 | 饰品店 | `accessory` | 配饰 | 独立空库 |

- 登录页选择店铺 → 输入密码（默认 `000000`，可自行修改账号资料）→ 进入。
- **数据完全隔离**：每账号使用独立 IndexedDB 库（`shoeErp_<账号id>`），互不共有。
- **经营范围过滤**：账号 1 只能看到「鞋」类商品，账号 2 只见「服装」，账号 3 只见「配饰」；开单、商品建档、库存、报表均按经营范围过滤。

### 2. 账号个性化

- 「我的」页可**修改店铺名称**（顶栏 / 侧栏 / 首页 banner 全局生效）与**上传店铺头像**（JPG/PNG ≤ 500KB）。
- 头像 / 店名会同步到账号列表，登录页同步展示。

### 3. 自建账号

- 登录页「＋ 新建店铺账号」可自行创建登录账户与密码。
- 自建账号默认**全部分类**开放（未分配经营范围），最多 **10 个**账号。

### 4. 云同步按账号隔离

- 每账号的 GitHub 同步配置独立存储（`erp.sync.config.<账号id>`），上传路径独立（`data/<账号id>/erp-snapshot.json`）。
- 各账号之间**数据互不干扰**，同步口令各自独立。
- 数据仅存本机浏览器与各自云端，**本地账号密码只存哈希，不同步上传**。

### 5. V2 存量数据

- 首次使用 V3 时，V2 单账号存量数据自动迁移到**账号 1（鞋店）**，迁移只执行一次。

## 一、运行方式

### 电脑本地（最简单）
直接用浏览器**双击 `erp/index.html`** 即可打开使用（运行于 `file://`）。
> 注意：`file://` 下浏览器禁止实时摄像头扫码，会自动降级为「拍照识别 + 手输」，其余功能完全正常。

### 手机端（推荐，功能最全）
1. 将整个 `erp/` 目录上传到任意一个**免费 https 静态空间**（如 GitHub Pages、对象存储静态网站、Netlify 等）。
2. 手机浏览器打开该地址 → 点「添加到主屏幕」→ 像 App 一样打开。
3. 此时**实时扫码**与**蓝牙打印**全部可用（需 Android + 支持 Web Bluetooth 的浏览器）。

### 离线可用
经 https 托管后，Service Worker（`sw.js`）会缓存应用外壳，断网后仍可打开使用。

## 二、备份纪律（重要）

数据只存在本机浏览器，清缓存 / 换手机 / 重装浏览器都会丢数据。请遵守：

- **每天**在「我的 → 设置 → 导出备份」导出一份账本 JSON。
- 电脑硬盘 + 网盘**各存一份**。
- 首页会显示「N 天未备份」提醒条，看到就导出。
- 导入备份会**整体覆盖**当前数据，导入前会二次确认。

## 三、核心业务闭环（PRD 第 10 节）

| 条目 | 能力 | 状态 |
| --- | --- | --- |
| 10.1 ① | 进货 → 库存联动 + 销售出库 + 收入流水 | ✅ |
| 10.1 ② | 混合赠送单（赠品行不计收入、单独记成本） | ✅ |
| 10.1 ③ | 退货红冲（库存回补 + 收入冲减） | ✅ |
| 10.1 ④ | 进货欠款 → 供应商付款冲减 | ✅ |
| 10.1 ⑤ | 客户挂账 → 回款冲减 | ✅ |
| 10.1 ⑥ | 单据作废（库存/流水/欠款全部回滚留痕） | ✅ |
| 10.2 | 三层利润（收入/成本/毛利/赠送成本/净利）+ 库存资金占用 | ✅ |
| 10.4 / 10.5 | 首页看板（今日概览/预警/超期欠款/趋势图/TOP5） | ✅ |
| 10.6 | 扫码三级降级（实时 / 拍照 / 手输）+ 商品卡 | ✅ |
| 10.7 | 条码渲染（CODE128）+ 标签版式 + 蓝牙打印（TSPL/ESC-POS） | ✅ |

**设计原则**：单据是唯一事实来源，库存、流水、欠款全部由单据派生，禁止任何「手改余额」入口。金额一律以「分」为整数存储，显示时除 100，避免浮点误差。

```

│   ├── store/            # IndexedDB 封装 + 工作上下文

│   ├── barcode/          # 渲染 / 标签 / 扫码 / 蓝牙打印
│   └── app.js            # 启动、落库、锁屏
└── tests/                # node --test 全部用例
```

## 六、打印机与扫码注意事项

- **条码打印扫不出**：静区 ≥ 2.5mm、模块宽 ≥ 0.375mm、打印浓度在打印机驱动里调、先用「测试页 TEST001」验证。
- **蓝牙机型指令不兼容**：先用测试页验证；都不行则走「导出 PNG/PDF → 厂商 App 打印」兜底。
- **iPhone**：无法蓝牙 / 实时扫码，走拍照识别 + 手输 + 电脑端代打。

## 七、技术栈

- 原生 JS（无框架、无构建、无 npm 依赖），经典 `<script>` 按序加载 + 全局 `window.ERP` 命名空间。
- **不使用 ES Module**（`file://` 下 `<script type="module">` 会被 CORS 拦截）。
- 第三方能力以本地文件随包发布，离线可用。
