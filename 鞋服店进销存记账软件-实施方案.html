1现状与需求分析

先把你现在"手工记账乱"的根源拆开看，才能对症下药。

手工记账的典型痛点

  • 账分多处：进货记一个本、销售记一个本、库存靠脑子记，月底对不上。
  • 鞋服特有的复杂度：同一款鞋有多个颜色 × 尺码，库存必须精确到"款-色-码"这一级，普通记账软件管不了。
  • 赠送说不清：送出去的货既没收入也不是"卖丢的"，手工账里通常直接消失，导致库存越对越乱、利润虚高。
  • 欠款没台账：赊账进货（欠供应商）和赊账销售（客户欠你）只记在脑子里。
  • 利润算不清：只记收入不记成本，月底不知道到底赚了多少。

2总体架构方案（零服务器）

核心思路：做一个纯网页应用（Web App），手机和电脑用浏览器打开就能用，数据存在设备本地，不依赖任何服务器。

图 1 · 总体架构：手机与电脑打开同一个网页应用，数据默认存本地，可选云同步

为什么选"纯网页应用"而不是买现成软件？

✔ 数据完全归自己

不用把进货价、利润这些商业机密交给第三方 SaaS 平台；本地数据随时导出。

✔ 零成本零维护

没有服务器租金、没有年费、没有宕机风险；一个文件就是一个系统。

✔ 完全贴合鞋服业务

颜色×尺码库存、赠送记账这些功能，通用记账软件几乎都做不了，定制开发则要上万。

✔ 手机电脑同一套数据界面

手机开单快、电脑看报表爽，同一套系统自适应两种屏幕。

图 7 · 数据模型关系图（核心 6 张表，单据保存时自动联动）
关键设计：销售单里保存"进价快照"。每笔销售发生时，把当时该商品的进价一起记进单据。这样无论以后进价怎么涨跌，历史利润永远算得准，不会被后来的调价污染。

7利润计算方法

不再"只记收入不算成本"，报表里给你三层利润，一眼看清赚在哪里。

① 营业额= 所有销售单金额合计（不含赠送）
② 毛利= 销售收入 − 已售商品的进价成本（含退货冲减）
③ 净利参考= 毛利 − 房租/水电/人工/物流/赠送成本等支出
计算项口径说明示例（某月）
销售收入销售单实收 + 挂账欠款（权责发生，退货运单红冲）¥ 68,420
销售成本每笔销售按"进价快照"累计¥ 47,120
毛利 / 毛利率收入 − 成本¥ 21,300 / 31.1%
赠送成本赠品按进价计，单列（不计入销售成本，避免毛利虚低）¥ 860
固定与费用支出房租、水电、人工、物流、平台费等¥ 5,800
净利参考毛利 − 赠送成本 − 费用支出¥ 14,640
库存资金占用当前库存 × 最新进价（压了多少钱在货上）¥ 32,500
口径提醒：进货付款 ≠ 当月成本。比如 8 月进 1000 件只卖了 300 件，利润只扣 300 件的成本——这正是很多手工账"感觉没赚却不见钱"的原因：钱变成了库存。报表会同时给出"利润"和"库存资金占用"两个数字。

8实施路线图（4 个迭代，边用边完善）

不用等全部做完才开始用——每阶段结束都能立刻上手用起来。

阶段 0 · 需求确认与设计定稿

耗时：半天 ｜ 交付：最终版原型图 + 字段清单
  • 确认你的商品类别（鞋/服装/裤/配饰）、常用尺码段、是否需要条码
  • 确认赠送场景细分（赠品/样品/自用/破损）与是否需要拍照留底
  • 确认欠款习惯（客户挂账上限、供应商结算周期）

阶段 1 · 地基：商品档案 + 进货 + 库存（第一周）

交付：手机/电脑均可用的第一版系统
  • 商品档案：款号、颜色尺码矩阵、进售价（支持批量导入 Excel）
  • 进货单录入、修改、作废；库存自动增减与流水
  • 库存查询（按款/色/码）、低库存预警
  • 存量商品初始化：录入现有库存（支持盘点导入）
  • 上线动作：把在售款式一次性建档，先只用于"进货 + 查库存"

阶段 2 · 核心：销售开单 + 赠送 + 记账（第二周）

交付：日常经营全流程数字化
  • 手机快速开单（搜索、色码选择、改价、折扣、多种收款）
  • 赠送出库单独类型；销售退货红冲；进货退货
  • 收支流水自动生成 + 手工记账（房租水电等）
  • 客户/供应商欠款台账与还款登记
  • 上线动作：从此停用手工账本，全部单据走系统

阶段 3 · 经营：报表利润 + 备份安全（第三周）

交付：看得懂的经营账
  • 经营看板：日/月销售额、三层利润、畅销滞销排行
  • 报表导出 Excel / 打印；月末库存盘点与差异调整
  • 一键备份导出 JSON、导入恢复；支持设置打开密码
  • 上线动作：建立"每日关店一键备份"习惯

阶段 4 · 增强：跨设备同步 + 打磨（第四周起，按需）

交付：手机电脑数据实时一致
  • 方案 A（免费）：备份文件互传——手机导出→电脑导入，适合一天同步一两次
  • 方案 B（免费额度）：接入云同步（腾讯云 CloudBase 等），手机电脑实时一致
  • 扫码枪/条码打印、小票打印机对接（如店里需要）
  • 性能优化：万级单据下手机端依然流畅
手机上的使用方式（上线当天就要做）：用手机浏览器打开系统地址 → 菜单选"添加到主屏幕"→ 桌面出现 App 图标 → 点击全屏使用，和微信一样方便。电脑端建议收藏到浏览器书签栏，或打包成双击即开的桌面程序。

＋补充：条码与扫码功能（2026-08-30 增补）

最新要求（2026-08-31）：填「名称、类别、颜色、号码」自动生成款号 / SKU id / 条形码；手机蓝牙直连热敏机打标签；扫码直达该色码看库存并销售。以下内容已同步写入 PRD 第 11 节。

0. 编码自动生成（2026-08-31 最新要求）

建档只填 4 项：名称、类别、颜色、号码（再加进价/售价），系统自动生成款号 → SKU id → 条形码。
条码 = 款号，同款只用一条码（白/38、白/39、黑/38 的标签条码完全相同，只有文字不同） • SKU id 每个"颜色+号码"唯一，作为库存与单据的内部主键；扫码后弹库存矩阵，点格子销售
图 8 · 填 4 项自动生成款号、SKU id 与条码
组成规则示例
类别字母鞋 X / 服装 F / 裤 K / 配饰 P / 包袋 B / 其他 O（设置里可自定义）鞋 → X
款流水该类别内 3 位递增（001–999），同款共用第 1 款 → 001，款号 X001
色序同款内按录入顺序自动编号 2 位；同色复用同序号白→01，黑→02
尺码码清洗为安全字符：38→38、XL→XL、38.5→385、39/40→39-4038 码 → 38
完整 id拼接后校验全局唯一，冲突顺延X0010138

同款判定：名称 + 类别完全相同 → 复用已有款号，只新增 SKU（白/39 → X0010139；黑/38 → X0010238）。重复拦截：同款下"颜色+尺码"已存在则提示不重复生成。款号可手动改（改后同步该款全部 id 与条码，并提示重打标签），id 生成后不可改。

1. 条码绑定层级：款级（同款一个条码，条码 = 款号）

同一个款只用一个条码，不需要每个单件都唯一。条码内容 = 自动生成的款号（如 X001）。
每个"颜色+号码"仍自动生成 SKU id（X0010138）作为系统内部主键（库存、单据明细、盘点追溯），但不印进条码。
扫码 → 弹出该款的售价与"颜色×尺码"库存矩阵 → 点一下格子就卖出该色码。同款各色码的标签条码相同、文字不同。
图 8B · 扫码后的主视图：该款库存矩阵（点格子即销售，0 库存灰显）

2. 条码从哪来：现成吊牌 + 系统生成

来源场景处理方式
A. 供应商吊牌现成条码商品自带条码建档点【扫码录入】扫进来，或手工输入
B. 系统生成（店内码）没有现成条码的商品系统按规则自动生成 → 打印标签 → 贴上即可扫码使用

生成规则：默认 CODE128（内容=款号，如 A101，支持字母数字，扫码枪与手机都能识别、长度短好打印）；可选 EAN-13 店内码（13 位数字，前缀用国际保留的店内码段 20–29，不会与外部商品码冲突，末位为标准校验位）。生成即写入档案，记录"来源=系统生成 + 生成时间"。

3. 条码生成与打印（手机蓝牙直连热敏标签机）

工作方式已确认：手机上建档 → 蓝牙直连热敏机立刻打出标签 → 贴到商品；销售时扫码 → 看库存 → 点尺码卖。打印机支持蓝牙、手机直连，全流程在手机上完成，不需要电脑常开。
平台限制（必须知道）：浏览器蓝牙打印依赖 Web Bluetooth，安卓（Chrome / Edge）可用，iPhone 的 Safari 不支持。若是 iPhone，走兜底：生成 PDF/PNG 分享给打印机厂商 App 打印，或加入待打印队列在电脑端打印；界面会自动隐藏蓝牙按钮，不会出现点了没反应的情况。
硬件：热敏不干胶标签机（蓝牙）+ 卷装不干胶标签，热敏模式无需碳带。这类机器对尺寸精度和缩放极敏感——一缩放，条码就可能扫不出来，所以以下参数在开发时写死。
参数默认设置为什么
标签尺寸40×30mm（可选 50×30 / 60×40 / 30×20）条码内容是 4 字符款号，40mm 宽足够；鞋服吊牌、鞋盒最常用
分辨率203dpi（机型支持可切 300dpi）40×30mm@203dpi ≈ 320×236px，条码位图按此计算
条码类型CODE128（内容 = 款号，如 X001）约 79 模块，40mm 标签下模块宽 ≈0.44mm，远超 0.25mm 下限，热敏打印清晰
条码高度10mm低于 8mm 手机摄像头很难识别
左右静区≥2.5mm（模板强制留白）静区不足是"打出来扫不出"的头号原因
字号商品名 10pt / 款号·售价 9pt / 条码数字 8pt热敏纸小于 8pt 容易糊
页面与缩放@page{size:40mm 30mm;margin:0}，一页一张，强制 100%纸张尺寸写死，防止浏览器自动缩放到 A4 导致条码变形

标签内容（自上而下）：店名（可开关）→ 产品名称 → 颜色 + 号码（尺码） → 价格 → 条形码 → 条码下方可读数字（破损时可手输）。

标签是"色码级"，条码是"款级"：同一款下每个"颜色×尺码"各打一张标签，条码内容相同（都是款号），文字不同（白/38、白/39、黑/38…）。每双鞋上都有写明颜色尺码的标签，扫码后弹出的是这一款的库存矩阵，点一下对应格子即可销售。

蓝牙打印实现要点（手机端主通道，开发必读）

  • 蓝牙通道：Web Bluetooth（navigator.bluetooth.requestDevice）连标签机，GATT 写特征发指令；要求 https 环境（正好由下面的托管方案满足）。
  • 指令适配层：内置 TSPL（TSC 兼容，多数国产标签机）与 ESC/POS 两套，设置里切换；首次使用打测试页选对指令（打出来是乱码就换另一个），选择本地保存。
  • 位图生成：标签先渲染成 1-bit 黑白位图，按 DPI 精确算像素（40×30mm@203dpi = 320×236px），禁止任何缩放拉伸，条码模块宽 ≥3px。
  • 连接体验：首次点【连接打印机】系统弹窗选设备（需用户手势触发）→ 记住设备，下次自动重连；断连给"重连 / 改用电脑打印"入口。
  • 先打测试页：【打印测试标签】（固定条码 TEST001），手机扫通才允许批量打，避免整卷浪费。
  • 电脑端备用通道：@page{size:Wmm Hmm;margin:0} 一页一张、1:1 不缩放、关页眉页脚；可导出 PNG/PDF（203/300dpi）给厂商软件打印；手机端待打印队列可同步到电脑一键批量打。
  • 打印记录：记录打印时间与张数、模板尺寸、对应色码，列表支持"已打印 / 未打印"筛选，避免漏打和重复打。

5. 识别方式三级降级（任何环境都能扫）

方式适用说明
① 实时预览扫码（首选）https 环境摄像头连续识别，支持连扫，体验最好；浏览器要求安全上下文
② 拍照识别（兜底）任何环境，含离线 file://调系统相机拍一张后本地解码，不要求 https
③ 手写输入条码破损/光线差/无摄像头直接输条码数字，结果与扫码一致

电脑端 USB 扫码枪本质是键盘模拟输入，光标在搜索框内即可直接使用，不需要额外开发。

条码生成与打印只在电脑端做（要接打印机），扫码使用主要在手机端，两端数据一致。

6. 部署方式微调（重要）

手机摄像头必须在 https 环境才能调用。推荐：把纯静态文件托管到免费 https 静态空间（EdgeOne Pages / GitHub Pages / Cloudflare Pages / 腾讯云 COS 静态网站），手机用网址打开并"添加到主屏幕"，配合 Service Worker 缓存后离线仍可打开。所有经营数据仍然只存在手机本地，服务端不存任何数据，依然零服务器成本。

如果只用本地文件双击打开（file://），实时扫码不可用，系统自动降级为"拍照识别 + 手写输入"，其余功能不受影响。

7. 异常条码处理

  • 未建档 → 提示"未找到此条码"，提供【立即建档】，跳转新建商品并预填条码。
  • 条码重复 → 建档/批量导入/生成时拦截，指出已被哪个款占用（款级唯一）。
  • 整款库存为 0 → 提示"此款已无库存"；单个色码为 0 → 矩阵中灰显不可点。
  • 已停售 → 查库存可见，销售扫码时二次确认。
  • 识别失败 → 提供【重试】【手输条码】两个入口。
